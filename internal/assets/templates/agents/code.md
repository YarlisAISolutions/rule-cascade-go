This project keeps its business rules in Rule Cascade rulesets (`{{rules}}/**/*.ruleset.yaml`), not in
application code. Follow "Business rules: Rule Cascade" in `AGENTS.md` and the `rules-cascade` skills.

When you add or change a validation, a limit, an eligibility check, a status branch or an approval:

- Look first whether a ruleset decides it: MCP `list_rules`, or `analyze` on the file (a hit with
  `coveredBy` names the ruleset). If one does, evaluate the ruleset (the engine on the server, the
  client manifest in the browser) instead of writing the check again.
- If none does, do not copy the value into code twice (once in the backend, once in the user
  interface): propose a rule with `propose_ruleset`, with golden tests, and use it on both sides.
- When the code and a ruleset disagree (`analyze` shows `drift`), say so; do not pick a value silently.
- `{{out}}/` is generated by `rcas compile --all`: never edit it.
